---
title: Installation
description: Add the automation module to an AntelopeJS DMS project.
mode: how-to
---

These steps add the module to a project that already loads `@antelopejs/dms`. The ranges of the DMS packages the module runs on are in the compatibility block of the [module README](https://github.com/AntelopeJS/dms-automation/tree/main/packages/dms-automation#compatibility).

::steps
### Add the module

```bash [Terminal]
ajs project modules add @antelopejs/dms-automation
```

The command installs the package and adds a `dms-automation` entry to `antelope.config.ts`. The module implements `@antelopejs/interface-dms-automation`, so the modules that declare nodes find it without more wiring.

### Configure it (optional)

The module runs without configuration. To change a default, add a `config` block to its entry:

```ts fragment [antelope.config.ts]
"dms-automation": {
  source: { type: "package", package: "@antelopejs/dms-automation", version: ">=0.8.0 <1.0.0" },
  config: {
    runs: { retentionDays: 30 },
    httpRequest: { blockPrivateNetwork: true },
  },
},
```

[Configuration](/docs/modules/automation/configuration) lists every option.

### Restart the backend, then the frontend

The module registers its Vue frontend module, with the `DmsAutomation` component prefix, when the backend starts. Restart the backend first. Then restart `ajs dms dev`, or rebuild the dashboard with `ajs dms build`.

### Create a procedure

Open **Automation** in the **Modules** group. While no procedure exists, the Overview offers three recipes to start from: **Forward a webhook**, **Send a scheduled digest** and **Run it on demand**.
::

::note
To upgrade from the CMS-era package, recreate the deployment. Release 0.0.1 of `@antelopejs/dms-automation` renamed the `cms-automation` database, the `cms_automation` schema, the `cmsAutomation` config key and the `cms-automation-<locale>` i18n namespace, and no migration path exists.
::
