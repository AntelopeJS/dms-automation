# Extending

Any module can add nodes to the automation builder. The contract lives in a separate package, [`@antelopejs/interface-dms-automation`](https://github.com/AntelopeJS/dms-automation/tree/main/packages/interface-dms-automation), which `@antelopejs/dms-automation` implements. A module that declares nodes depends on the interface only, never on this module.

## Add the interface

Choose the dependency type according to whether your module needs automation:

| Dependency type | Use when | Without the automation module |
| --- | --- | --- |
| `optionalDependencies` | Your nodes are a bonus. | Registrations wait for attachment. |
| `dependencies` | Your module needs automation to work. | Automation is required. |

For optional nodes, add the interface to `optionalDependencies`:

```json [package.json]
{
  "optionalDependencies": {
    "@antelopejs/interface-dms-automation": ">=0.2.0 <1.0.0"
  }
}
```

## Declare an action

Register in `start()`, unregister in `stop()`:

```ts [src/automation.ts]
import { RegisterActionType, UnregisterActionType } from "@antelopejs/interface-dms-automation";

const RESTOCK_ID = "bakery.restock-order";

export function registerAutomationNodes(): void {
  RegisterActionType({
    id: RESTOCK_ID,
    name: "Place restock order",
    description: "Order an ingredient restock from a supplier",
    icon: "i-lucide-shopping-cart",
    inputSchema: {
      type: "object",
      properties: { ingredient: { type: "string" }, supplier: { type: "string" } },
      required: ["ingredient", "supplier"],
    },
    outputSchema: { type: "object", properties: { ordered: { type: "boolean" } } },
    async execute(input, ctx) {
      ctx.log("info", "placing restock order", input);
      return { ordered: true };
    },
  });
}

export function unregisterAutomationNodes(): void {
  UnregisterActionType(RESTOCK_ID);
}
```

The builder lists the node in its palette under your module's name (as named in `antelope.config.ts`), with a settings panel generated from `inputSchema` and one output port per `outputSchema` property.

## Node kinds

Choose a node according to its role:

- A **trigger** starts a run.
- An **action** performs asynchronous I/O.
- A **data node** computes values synchronously and purely.

The [consumer reference](/docs/modules/automation/reference) defines the required
members, schemas, lifecycle and execution context for each kind.

### Trigger clustering

Choose the trigger's `cluster` mode based on where it should fire:

- `singleton` activates on the leader only.
- `replicated` activates on every instance.

## Run a procedure from code

```ts
import { InvokeProcedure } from "@antelopejs/interface-dms-automation";

const runId = await InvokeProcedure(procedureId, { orderId: "10477" });
```

The saved procedure needs a manual trigger. Inspect the run's recorded outcome
rather than treating its ID as proof of success. See the [invocation contract](/docs/modules/automation/reference#list-types-and-invoke-procedures)
for return values, failures and authorization responsibilities.

## Ship procedures as code

A project or a module can ship its own procedures, such as the automations a template provides, with `DeclareProcedure`. Call it on every boot from `start()`:

```ts [src/automation.ts]
import { DeclareProcedure } from "@antelopejs/interface-dms-automation";
import followUpQuotes from "./procedures/quote-follow-up.json";

export async function start(): Promise<void> {
  await DeclareProcedure({
    id: "bakery.quote-follow-up",
    name: followUpQuotes.name,
    description: followUpQuotes.description,
    graph: followUpQuotes.graph,
    enabled: true,
  });
}
```

Design the procedure in the builder, export it with **Export JSON**, and keep the file in your project. The `id` is yours and stays the procedure's ID: the call creates the procedure once, refreshes it when your declaration changes, and leaves it alone once someone edits, pauses or resumes it in the builder. An enabled procedure starts listening immediately, on every instance. The [declaration contract](/docs/modules/automation/reference#declare-procedures-from-code) gives the validation and the exact update rule.

Do not insert rows in the module's tables yourself: a procedure written behind the module's back is not armed until the next restart, and it ties your project to an internal schema.

## Fire on changes to your own tables

The **Table watch** trigger of [`@antelopejs/dms-database`](/docs/modules/database/extending#table-watch-automation-trigger) (`database.table-watch`) starts a procedure on each insert, update or delete in any registered table, your project's included. Set `schema` to the ID you pass to `RegisterSchema` and `table` to the table name.

::warning
It reads the database change feed. MongoDB only has one on a **replica set**: on a standalone server the procedure shows as Failing with "$changeStream is only supported on replica sets". In development, start MongoDB as a single-node replica set (`mongod --replSet rs0`, then `rs.initiate()` once) and add `replicaSet=rs0` to the connection string, or use a hosted cluster, which is always a replica set.
::

The trigger's output carries the row before and after the change, so the procedure can read your columns, a `tenantId` included. To act on tenant data from your own action, declare `tenantId` as an input and wire it from that output: the execution context of an action has no tenant.

## Nodes from other modules

| Module | Nodes |
| --- | --- |
| `@antelopejs/dms` | Triggers: member added and removed, invite created, user registered, record created, updated and deleted. Actions: send email, send notification, invite user. |
| [`@antelopejs/dms-database`](/docs/modules/database/extending#table-watch-automation-trigger) | Trigger: table watch. |
| [`@antelopejs/dms-api`](/docs/modules/api/extending#automation-nodes) | Trigger: route unhealthy. Actions: get API health, query request logs. |

## Role permissions

The module's pages are DMS blocks around a few module components (`DmsAutomation` prefix), each named for the roles screen with `.meta()`. The pages and the module's API (`/api/automation`) belong to the platform owner.
