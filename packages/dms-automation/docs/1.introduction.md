`@antelopejs/dms-automation` is the visual automation builder of the AntelopeJS DMS. A **procedure** is a graph of nodes. A trigger starts it: a schedule, a webhook, a click or a DMS event. Actions do the work, such as an HTTP call, an email or a notification. Data nodes shape the values in between. The module runs procedures, keeps every run with its trace, and tells you which procedures need attention.

## Building blocks

A procedure combines five kinds of blocks. The module ships the triggers **Manual**, **Schedule (cron)** and **Webhook**, the actions **HTTP request** and **Log**, the flow nodes and the data nodes in the table below. The DMS and other modules register the rest.

| Kind | Examples | Role |
| --- | --- | --- |
| Triggers | Manual, Schedule (cron), Webhook, and DMS events such as Member added, User registered and Record created | Start a run with a payload. |
| Actions | HTTP request, Log, Send email, Send notification, Invite user | Do something, in order along trigger edges. |
| Flow | If, Switch, For each, For range, Parallel, Try / Catch, Retry, Delay, Set variable | Branch, loop and recover. |
| Data nodes | Constants, Math, Comparison, Logic, Text, Objects, JSON | Compute values that data edges wire into fields. |
| Templates | Your own reusable groups of nodes | Share a sub-graph between procedures. |

The DMS registers the event triggers and the **Send email**, **Send notification** and **Invite user** actions. Other modules add their own nodes through [`@antelopejs/interface-dms-automation`](/docs/modules/automation/extending). `@antelopejs/dms-database` adds a **Table watch** trigger. `@antelopejs/dms-api` adds a **Route unhealthy** trigger and two actions, **Get API health** and **Query request logs**.

## Who it is for

The Automation pages sit in the DMS **Modules** group, which only the platform owner sees. The module's API follows the same rule: every route answers the platform owner only.

## Requirements

- A DMS backend and the `@antelopejs/dms-frontend` renderer in the ranges the module supports. The compatibility block of the [module README](https://github.com/AntelopeJS/dms-automation/tree/main/packages/dms-automation#compatibility) lists the `@antelopejs/interface-dms` range. The frontend module declares its renderer range in `engines["@antelopejs/dms-frontend"]` of `frontend-vue/package.json`, and the `ajs dms` CLI refuses to build the module with a renderer outside that range.
- An API provider, `@antelopejs/api`, for webhooks.
- A database implementation.
- Optionally, `@antelopejs/interface-redis`, to run several instances. See [Clustering](/docs/modules/automation/configuration#clustering).
