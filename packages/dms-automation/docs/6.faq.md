# FAQ

## My procedure is Failing but never ran

Its trigger cannot be armed: an invalid cron expression, or a webhook path already taken. The reason shows under its state on the Procedures page.

## My webhook path is refused

A path cannot overlap a route the API already serves, nor start with `/api`, `/auth`, `/dms`, `/modules` or `/settings`, and two enabled procedures cannot share the same method and path.

## The webhook URL shown in the builder has the wrong host

It is built on the DMS `apiBaseUrl`. Set it to the URL callers reach your API at.

## A re-run sent `[redacted]` instead of a token

Runs store credentials redacted. A re-run sends what was stored, so the redacted values go out as `[redacted]`; the confirmation warns about it. Add your own credential names with `runs.sensitiveNames`.

## Do test runs count in the figures?

No. Test runs from the builder keep a trace but never count in the states, KPIs or charts.

## How long are runs kept?

30 days by default (`runs.retentionDays`); `0` keeps every run. The leader instance deletes older runs every hour.

## A cron procedure ran twice, or skipped an occurrence

In a cluster, singleton triggers are fire-once in normal operation, not exactly-once across a leadership change. Make the procedure's effect idempotent. See [Clustering](/docs/modules/automation/configuration#clustering).

## The palette does not group nodes by module

The backend logs `type-origin attribution unavailable` when it cannot tell which module registered a node. Update `@antelopejs/interface-dms-automation` and the module together.
