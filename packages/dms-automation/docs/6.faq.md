## My procedure is Failing but never ran

Its trigger cannot be armed. Two common causes are an invalid cron expression and a webhook path that another route already answers on. An enabled procedure whose trigger failed to arm is **Failing**. The Procedures page shows the reason under its state, and the **Needs attention** list of the Overview shows it after `Trigger not armed:`.

## My procedure says a trigger type is not available

The module that registers that trigger type is not loaded, or failed to start. The reason reads `trigger type "<id>" is not available`. A type that registers late, from a module that starts after Automation or reloads in development, arms its procedures as soon as it registers.

## My table watch procedure is Failing with "$changeStream is only supported on replica sets"

The **Table watch** trigger reads the database change feed, and MongoDB offers that feed only on a replica set. Run MongoDB as a replica set. A single node is enough. See [Fire on changes to your own tables](/docs/modules/automation/extending#fire-on-changes-to-your-own-tables).

## A procedure my project declares did not update

`DeclareProcedure` writes a procedure once, when no procedure has its ID. A later declaration answers `kept` and never changes the existing procedure. Edit the procedure in the builder, or delete it so that the next declaration creates it again.

## My webhook path is refused

The module refuses a path that matches one of these cases:

- It does not start with `/`, or uses a character other than letters, digits, `-`, `.`, `_`, `~`, `:` and `/`.
- It is `/api`, `/auth`, `/dms`, `/modules` or `/settings`, or starts with one of them followed by `/`.
- A route the API already serves answers the same method on the same path.
- Another enabled procedure has a webhook with the same method on the same path. A `:param` segment matches any segment.

[Webhooks](/docs/modules/automation/configuration#webhooks) lists every rule.

## The webhook URL shown in the builder has the wrong host

The builder builds the URL on the DMS `apiBaseUrl`. Set `apiBaseUrl` to the URL callers reach your API at. When `apiBaseUrl` is not set, or is a loopback address, the URL uses the origin the dashboard reached the API on.

## A re-run sent `[redacted]` instead of a token

A run stores credentials redacted. A re-run sends what the run stored, so the redacted values go out as `[redacted]`. The re-run confirmation warns about it: `Credentials weren't kept and are sent as "[redacted]"`, followed by the header names. To redact more names, add them to `runs.sensitiveNames`. [Credentials in runs](/docs/modules/automation/configuration#credentials-in-runs) lists the built-in names.

## Do test runs count in the figures?

No. A test run from the builder is stored with its trace, but it never counts in the states, the KPIs or the charts.

## How long are runs kept?

30 days by default. `runs.retentionDays` sets the number of days, and `0` keeps every run. The leader instance deletes older runs every hour.

## A cron procedure ran twice, or skipped an occurrence

In a cluster, singleton triggers fire once in normal operation, but not exactly once across a leadership change. Make the effect of the procedure idempotent. See [Clustering](/docs/modules/automation/configuration#clustering).

## The palette does not group nodes by module

The backend logs `type-origin attribution unavailable` when it cannot tell which module registered a node. Update `@antelopejs/interface-dms-automation` and `@antelopejs/dms-automation` together.
